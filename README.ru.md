# Microform Code

### Бумага — носитель. Принтер — пишущая головка.

**Microform Code — плотный 2D-код для бумаги: каждая ячейка несёт 17 бит —
эллипс (угол, масштаб, вытянутость) плюс микро-точку со сдвигом;
детерминированный кодбук оставляет только наборы параметров, которые
рендерятся в визуально уникальные тайлы, а RS(255,223) защищает битовый
поток. При 300 мкм/ячейку стикер 30×30 мм хранит ~15 КБ — примерно ×5 к
QR-40 того же размера.**

## Что такое Microform Code?

Один Rust-крейт (edition 2021, две зависимости: `png` и `reed-solomon` —
всё остальное, от порога Отсу до решателя гомографии, написано здесь),
закрывающий всю историю бумажного кода:

* 🧬 **17 бит на ячейку** — повёрнутый/масштабированный/вытянутый эллипс
  (10 бит) плюс микро-точка со сдвигом (7 бит); из 262 144 комбинаций
  параметров **184 154** дают различные тайлы при канонических 14 px/ячейку,
  кодек использует первые 131 072 = 2¹⁷ из них
* 🗝️ **Детерминированный кодбук** — декодирование это точный lookup
  пиксельного тайла, без эвристик; сборка — фиксированный цикл обхода,
  одинаковая на любой машине, ~0.4 с в release
* 🛡️ **RS(255,223) с чистой изоляцией** — один RS-блок это ровно
  255 байт = 2040 бит = **120 ячеек**; ошибка ячейки задевает ≤ 3 байта,
  значит **5 ошибок с неизвестными позициями** на блок исправляются
  гарантированно, а **10 известных отсутствующих ячеек** (штамп, клякса)
  восстанавливаются как стёртия
* 📐 **Масштабо-осведомлённое декодирование** — шаг сетки измеряется по
  угловым маркерам; каждый масштаб получает собственный кодбук из тайлов,
  уникальных на этом масштабе, а битовая глубина ячейки подстраивается
  (17 → 15 → 12 бит — всегда делитель 2040-битного блока)
* 🖨️ **Дружелюбно к печати** — чистый чёрно-белый растр, сетка
  определяется автоматически, тихая зона нужна всего в 1 ячейку

## Сравнение с QR

| Параметр | QR-40 | Microform (300 мкм) | Microform (200 мкм) |
| --- | --- | --- | --- |
| Физический размер | ~30×30 мм | **30×30 мм** | **31.6×31.6 мм** |
| Сетка | 177×177 модулей | 92×92 ячеек | 150×150 ячеек |
| Бит на модуль | 1 | **17** | 15 |
| Сырая ёмкость | ~3 КБ | 17.4 КБ | 41.1 КБ |
| Полезная нагрузка | ~3 КБ | **15.2 КБ** | **35.9 КБ** |
| Коррекция | RS | RS(255,223), 70 блоков | RS(255,223), 161 блок |
| Гарантированное восстановление ячеек | — | 5 ошибок или 10 стёртий / 120 ячеек | 8 ошибок или 13 стёртий / 136 ячеек |
| Печать | любая | офисный лазер, 1200 dpi | офисный лазер, максимум |
| **Ёмкость против QR** | **1×** | **~5×** | **~12×** |

## Быстрый старт

```bash
# готовые бинарники Linux/macOS/Windows: https://github.com/kostyk348/microform-code/releases
cargo install --path .          # или: cargo build --release

microform encode --data "Hello, paper!" -o hello.png
microform decode hello.png --text
microform capacity              # три печатных пресета
microform demo                  # 8 честных проверок, ~2 с
```

Как библиотека:

```rust
use microform::{generate, pngio, decode_png, RenderSpec};

let img = generate(RenderSpec::default(), b"Hello, paper!");
pngio::write_gray("hello.png".as_ref(), &img).unwrap();
assert_eq!(decode_png("hello.png".as_ref(), None).unwrap().data, b"Hello, paper!");
```

## Как это работает

1. **Фрейминг** — к данным добавляется 4-байтовый префикс длины, поток
   заполняет целые блоки RS(255,223), остаток ёмкости — детерминированный
   PRNG-шум, чтобы код выглядел однородной текстурой без пустых прогалов.
2. **Ячейки** — каждое 17-битное значение (или глубина, адаптированная под
   масштаб) выбирает один канонический тайл из кодбука; тайлы рендерятся
   в масштабе печати.
3. **Рамка** — четыре угловых маркера 2×2 ячейки, шахматная рамка
   в 1 ячейку (та самая линейка, по которой декодер измеряет шаг сетки).
4. **Декодирование** — Отсу → эрозия → связные компоненты находят маркеры;
   4-точечная гомография отображает сетку ячеек на изображение; каждая
   ячейка приводится к тайлу и ищется в кодбуке; неизвестные тайлы
   становятся RS-*стёртиями* (позиции их байтов известны!) — бюджет
   восстановления удваивается.

## Честные части

* **Точный lookup хрупок.** Чистый растр декодируется идеально на любом
  поддерживаемом масштабе; *шум, размытие или фотография ломают хеш
  тайла*. Демо намеренно показывает границу: сильный шум
  **сообщается**, а не угадывается. Декодирование с камеры требует
  перцептивного сопоставления — это дорожная карта, а не заявление.
  См. [LIMITATIONS.md](LIMITATIONS.md).
* **Масштаб — параметр формата.** Код, напечатанный при 7 px/ячейку, и код
  при 14 px/ячейку используют разные (детерминированно выведенные)
  таблицы кодов; декодер определяет масштаб по самому изображению.
* Python-прототип, с которого начался этот репозиторий, живёт в
  git-истории; с v1.0.0 эталонная реализация — Rust-крейт.

## Структура проекта

```
src/layout.rs      — геометрия, пространство параметров, упаковка значений
src/patterns.rs    — маски эллипса/точки, канонический рендер тайла
src/codebook.rs    — детерминированная сборка, выборка 2¹⁷, масштабные книги
src/codec.rs       — RS-фрейминг, PRNG-паддинг, декод со стёртиями
src/render.rs      — холст: маркеры, шахматная рамка, ячейки данных
src/imgproc.rs     — Отсу, эрозия, связные компоненты, размытие, шум
src/homography.rs  — точный решатель DLT по 4 точкам
src/locate.rs      — поиск маркеров, оценка шага и размера сетки
src/decode.rs      — масштабо-независимый конвейер декодирования
src/demo.rs        — 8 честных проверок
src/main.rs        — CLI без зависимостей (encode/decode/capacity/codebook/demo)
tests/             — кодбук, кодек, roundtrip, CLI (24 теста)
```
