# Changelog

All notable changes to Microform Code are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/), versions follow
semver.

## [1.1.0] — 2026-10-30

The perceptual audit release: "visually unique tiles" becomes a measured
claim instead of a hand-wave, and Android joins the release targets.

### Added
- `microform perceptual` — a per-scale perceptual audit. Usable tiles are
  bucketed by a coarse appearance hash and compared pairwise (mean
  absolute difference + L∞); at the canonical scale every usable code is
  additionally compared to all one-step parameter neighbours. Measured
  reality at 14 px/cell: the closest usable pair differs by 1 gray level
  on 1 pixel (MAE 0.005/255); 221 of 8.59×10⁹ pairs are within L∞ ≤ 2 —
  the honest input for the RS budget, with the decode-path consequences
  spelled out. 4 new tests (28 total).
- Android release targets: `aarch64-linux-android`, `armv7-linux-androideabi`
  and `x86_64-linux-android` binaries (NDK r27d via cargo-ndk, API 24)
  attached to every release — runnable on-device in Termux or via adb.
- Audit building blocks in the library API:
  `perceptual::{audit_scale, neighbour_margins, describe_delta}`,
  `codebook::ScaleCodebook::iter_usable`, public
  `codebook::render_tile_at`.

### Changed
- The "visually unique tiles" claim in the README is now backed by the
  audit: fragile pairs (L∞ ≤ 2) do exist — 221 at the canonical scale,
  1,828 at 7 px — and are documented with their consequences (a wrong
  read requires a byte-exact reproduction of the partner tile; anything
  else degrades to an erasure) instead of being glossed over.
- The README documents that the usable count is non-monotone in scale
  (121,285 usable at 28 px/cell: the dot radius is specified in pixels
  and does not scale with the cell), which is why the cell depth drops
  to 15 bits at both ends of the supported range.

## [1.0.0] — 2026-10-30

The first complete release. The Python prototype (flat scripts, cv2 +
numpy + reedsolo, decode bound to exactly 14 px/cell and a 92×92 grid)
is superseded by a Rust crate; the prototype remains in git history.

### Added
- Rust crate `microform` (edition 2021, dependencies: `png`,
  `reed-solomon`) with a library API and a hand-rolled CLI:
  `encode`, `decode`, `capacity`, `codebook`, `demo`.
- Deterministic codebook: 262,144 parameter combinations → 184,154
  distinct tiles at 14 px/cell, codec uses the first 2¹⁷; full build in
  ~0.4 s, no cache file, byte-identical on every machine.
- Scale-aware decoding: pitch measured from markers, per-scale codebooks
  of tiles that stay unique at that scale, cell bit depth adapts
  (17/15/12 bits — always a divisor of a 2040-bit RS block).
- Reed–Solomon erasure decoding: cells that do not match any tile are
  recovered as erasures with known byte positions (10 cells per block
  versus 5 unknown-position errors).
- Partial RS blocks: grids smaller than one 255-byte block now carry
  data (minus parity and the length prefix) instead of being useless.
- Grid auto-detection from marker geometry with candidate validation by
  codebook hit-rate; explicit `--grid` override.
- Dependency-free image toolkit: Otsu threshold, binary erosion,
  connected components, exact 4-point homography (DLT + Gaussian
  elimination), box blur, deterministic noise.
- `microform demo` — 8 deterministic honest checks, including the
  deliberate boundary (heavy noise is reported, not guessed).
- 24 tests: codebook determinism/bijection, RS error and erasure
  guarantees, capacity math, end-to-end roundtrips at 7/14/28 px/cell,
  CLI integration; CI runs them with fmt + clippy on Linux and a
  best-effort Windows/macOS build.

### Changed
- Reference numbers moved from the Python rendering (188,819 distinct
  patterns) to the Rust rendering (184,154) — the pixel-center
  convention differs by design; the build loop is fixed, so the count
  is stable.
- Error-correction claims are now backed by tests: ≥5 unknown-position
  cell errors or ≥10 erasures per 120-cell block (the prototype's README
  claimed 5.9% of cells, which the RS math does not support).
- Demo PNG artifacts regenerated by the Rust implementation; heavy
  2 MB prototypes removed.

### Removed
- All Python prototype scripts (`codec_17bit.py`, `gen17.py`, `dec17.py`,
  `codebook_builder.py`, legacy 18-bit codec, debug utilities) — the
  Rust crate replaces them; see git history.

## [0.1.0] — prototype history

Pre-release evolution of the Python prototype: 10-bit ellipse codec,
18-bit dual-element iteration, codebook-based 17-bit decoder with the
first 100% loopback roundtrip, RS blocks padded with PRNG noise,
corner markers and checkerboard border. See the commit log.
